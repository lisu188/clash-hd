# Slots canvas lifecycle: controlled boundary protocol

This is an additive, source-only diagnostic interface for the separate
`-completehd-modalslots-validation` stage. It prepares the unchanged barracks
first-present probe and a separate continuation. No lifecycle runtime host is
implemented or run by this module. Complete lifecycle acceptance remains
**incomplete**, even when its strict boundary parser finds the expected sequence.
The protected stable stage, `complete_hd_v1`, launcher defaults, and historical
first-present/primary capture producers remain unchanged.

The source is `tools/modal_slots_lifecycle_probe.py`; its focused offline
fixtures are `tools/test_modal_slots_lifecycle_probe.py`. Preparation rebuilds
the entire slots candidate, manifest and sibling CDB probe through the existing
`modal_slots_candidate_context.py` contract. It authenticates the original SHA,
exact candidate SHA, resolution, recipe, source hashes, inherited packet and
both generated command artifacts. It rejects unknown native bytes, altered
generated leave code, unknown modal breakpoint IDs, conflicting sites, and an
unexpected inherited callback-return rejection. Source hashes are checked both
before and after preparation; a concurrent source edit rejects the packet.

## Two separate command artifacts

`prepare(..., mode="controlled_native_exit_map_redraw", ...)` returns:

- `initial_probe`: the exact current `modal_slots_barracks_trace.compile_probe`
  output, unchanged and identified by SHA-256.
- `continuation_probe`: deterministic commands for the authenticated paused
  boundary at `00433E77`. The packet binds its SHA-256 and every loaded byte
  check. This artifact is not an arbitrary host-supplied action.
- `packet`: the entire inherited packet, native/generated byte records, modal
  state layout, 35 boundary definitions, source hashes, explicit write records,
  and false runtime/acceptance flags.

A future host must first authenticate and accept the full original map trace,
initial modal route and twelve slot-copy observations using the unchanged
inherited evaluator. Only then may it load the separate continuation into the
same owned, paused debugger process. The continuation verifies the first-present
thread, instruction, root stack, original sentinel, canvas state, and inherited
debugger counters. It retires the initial observers, replaces only the known
`0042262E` callback-return rejection with the lifecycle observer, and retains
the fatal `00406FA1` synthetic-root-return guard.

There is no launcher integration, execute flag, host process API, input API or
runtime launch in this batch. The CLI prints preparation JSON; its exit-zero
result means packet generation only. It never means release eligibility.

## Controlled exit requests and actual native execution

The inherited entry remains a disclosed synthetic root call followed by a
controlled native case dispatch and one forced flipping-gate result. This
continuation adds exactly two target-memory writes. It never changes EIP, ESP,
return addresses, callback arguments, or saved ownership fields.

| Request | Guarded boundary | Target write | What executes afterward |
| --- | --- | --- | --- |
| Barracks exit | `00433EE9`, after all three initial presents and native loop initialization | `00532148: 0 -> 1` | The native loop falls through its exit branch, restores `00526A30`, releases barracks resources and returns through `00433F92` or `00434101` to `0042262E`. |
| Overview exit | `004226D8`, after the recreated overview draw and present return | `00526E80: 0 -> 1` | The ordinary overview exit path at `004223D3` executes native cleanup, the installed canvas leave wrapper, and restored-map drawing. |

Each write has a separate `LCAP_WRITE` record containing the observed old value,
new value, target address, thread, EIP and ESP. Its following event records the
actual post-write flag. The destructive-building flag `00526E84` must remain
zero. Repeated or already-set requests fail.

The native Back descriptors are `00514FC0 -> 004338C0` for barracks and
`00513D98 -> 00420840` for overview. This controlled protocol does **not**
exercise either descriptor, button animation, hit-test or callback. Their
native anchors `(39,426)` and `(31,432)` are inventory information, not verified
click rectangles. Observation of real Back input needs its own future path.

## Ownership, destruction and map boundaries

Let `R` be the actual canvas root-entry ESP recorded by the inherited probe.
All events bind the same thread and latched native header/pixels, physical
header/pixels and saved render device. Native headers remain separate from the
overview hit-map owner at `00526A68`.

| Boundary | Root-relative ESP | Required observation |
| --- | --- | --- |
| Remaining barracks presents and exit branch | `R - 84` | The owned native canvas stays active, with one allocation and no frees. |
| Barracks RET / parent continuation | `R - 60` / `R - 56` | The native RET has `0042262E` on its real stack. The parent recreates a separate hit map and completes overview drawing/presentation. |
| Installed leave wrapper / public `try_leave` | `R - 60` / `R - 100` | The real caller is `004224B7`; `try_leave` receives the actual wrapper-entry stack. |
| Owned scalar destructor CALL / entry | `R - 136` / `R - 140` | Globals already point to the borrowed physical surface and saved render device. State phase/native ownership is cleared before the call to `00403E50`; EAX is the latched native header and EDX is 2. |
| Pixel free CALL / entry / return | `R - 148` / `R - 152` / `R - 148` | `00403E6D -> 004740DD -> 00403E72` releases exactly the owned pixel pointer. |
| Header free CALL / wrapper / heap / return | `R - 148` / `R - 152` / `R - 152` / `R - 148` | `00403EA4 -> 00461C70 -> 004740DD -> 00403EA9` releases the owned header. |
| Before restored map / map entry | `R - 60` | Ownership pointers/thread/root are cleared; allocation/free counters are 1/1; leave status is 1; fault remains zero. |
| Full map CALL / return | `R - 72` | `0040AD8D -> 00418700 -> 0040AD92`, with the native present flag and restored physical render target. |
| Map RET / safe stop | `R - 60` / `R - 56` | `0040ADE0` returns to `004224B7`, where execution stays paused. |

Generated wrapper/destructor-call addresses are derived from the exact rebuilt
modal metadata and authenticated generated code. The known native addresses
have independent original-byte checks and repeated loaded-image byte checks.
Shared destructor/free routines also handle unrelated game allocations; those
are filtered by the latched owned addresses. A repeated event involving either
owned address is a failure. The protocol never dereferences the native header
after its destruction, and it never substitutes a resource count for the
required owned pixel/header call sequence.

The stop at `004224B7` is deliberate. The inherited fixture entered the root
with a synthetic return to `00406FA1`, which skips the interrupted function's
first push. Continuing the final root RET would not prove a natural return and
would risk an invalid stack. A real map-root caller chain, such as
`004094EB -> 0041EC70 -> 00422180`, needs a separate reviewed route.

## Diagnostic parser and incomplete acceptance

`evaluate_boundary_sequence` retains every raw lifecycle record and rejects
missing, duplicate, reordered, malformed, unknown or unmatched events. It
checks thread/allocation identity, stack deltas, native call/return identities,
both old/new request records, phase and ownership transitions, counts, and the
pixel-before-header destruction sequence. Its result is a **boundary sequence**
diagnostic. It does not authenticate arbitrary packets or logs by itself.

`evaluate_trace` first reconstructs the whole packet and both command artifacts.
It splits only at the one exact inherited host-ready marker, runs the unchanged
inherited evaluator on the complete prefix, and preserves every original
failure. The continuation's beginning must match the prefix's owned-canvas
readiness identity. Retired MCAP/SCAP/PTILE records in the lifecycle interval
are rejected instead of discarded.

Every result still returns `passed=false`, `evaluator_complete=false`,
`runtime_ready=false`, `healthy_map_redraw_proven=false`, and false input,
callback, continuity, cleanup and promotion flags. The explicit outstanding
failure is `complete lifecycle evaluator and restored-map evidence are not
implemented`. No generated report or deferred decision can satisfy acceptance.

The next bounded batch must add an owned hidden host, deadline/final-log and
cleanup verification, complete restored-map progress/coverage evaluation,
matching native visibility and surface evidence, and before/after captures.
Allocation-failure handling, ordinary Back callbacks, real root return,
save/load, player/day advancement, visible composition and manual input remain
separate open evidence requirements.
