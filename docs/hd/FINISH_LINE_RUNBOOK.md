# Local release-validation runbook

Release validation that requires the original game is **local-only**.

Full HD completion requires the [36-cell profile/preset matrix](RESOLUTION_RELEASE_MATRIX.md).
The versioned matrix-cell release context replays source-bound resolution
metadata only. Its fifteen runtime lanes, installed expanded battle and
promotion remain separate unfinished requirements; do not reuse the narrow
legacy 1920x1080 panel proof for another context. Source fixtures establish
neither a release nor a new runtime pass.

Expanded-battle preparation now includes separate uninstalled fresh field-loss,
eleven-site Tile replay and seventeen-site content replay successors. Their
source/CPU checks do not make expanded battle an installed feature. Count's
earlier record reads have a separate uninstalled entry-guard prototype below;
post-return gates,
primitive/line successors, provider/RLE lifetime, clipping, native ABI and healthy
return remain unfinished. Use [the tracked handoff](AGENT_HANDOFF.md) and exact
component reports for these boundaries. Do not use modeled scalar outcomes as
runtime, manual input, endurance, release-cell or promotion proof.
The [Count live-EBP audit](../../reports/battle-count-native-ebp-blocker-20261014.json)
also excludes the current two Count-body hooks from installation. A separate
fresh successor must replace the inherited Unit-EBP assumption with Count's
authenticated live neighbor-Y authority; preserving old model passes is not a fix.
The separate [final Adjacent-to-Unit audit](../../reports/battle-adjacent-unit-ebp-blocker-20261014.json)
also excludes five Unit body hooks: this signed-negative caller's saved EBP is
not admitted TileY. Correct its own source-bound caller contract and prove the
genuine final route separately; Count-only correction is insufficient.
The separate Count-entry checkpoint now checks draw-only input-record bounds
against an authored normal-RET stub. Its source/model pass neither executes the
original Count body nor repairs those downstream or final-caller blockers.

## Public prerequisites

Before any local runtime work:

1. Public-source boundary check passes:
   `python tools/check-public-boundary.py`.
2. Relevant source-only patch/launcher tests pass.
3. The candidate is produced outside the repository from a user-supplied,
   lawfully obtained executable.
4. The patcher verifies the expected executable hash and all old bytes before
   writing replacements.

## Local runtime validation

Use an isolated candidate directory outside the checkout. Keep the original
executable unchanged. Runtime checks may cover startup, menus, map rendering,
input, modal screens, battle rendering, save/load continuity, and endurance as
appropriate to the candidate.

Screenshots, captures, debugger logs, dumps, saves, and other retail-derived
evidence must remain outside public source control. Record only concise,
non-proprietary conclusions when updating public documentation.

## Promotion

A profile or resolution is promoted only when its source-level checks and the
required local runtime validation have both succeeded for the exact candidate.
A passing public CI job alone never establishes runtime acceptance.
