# Complete-HD army input validation

The army input lane uses the exact `complete_hd_v1` candidate and keeps its
protected stable predecessor unchanged. A new controlled selection protocol
reconstructs the complete manifest and executable before emitting commands.
All six supported resolutions use their own surface dimensions, capture byte
counts, emitted army entrypoints and overflow bounds.

The inspected scene remains the known slot0 save
`4f2182409d209985a527f07c4116b19e44332416698d6acb0a3d35ae68db8a89`.
Army 3 at `(16,19)` belongs to player 0 and has eight squads. Selection sets one
disclosed camera/mouse state and invokes native selection and redraw routines.
Actual selection, paired draws and the final stopped return must be observed.
No selected index, unit record, visibility, availability or callback result is
forced. This is controlled native-call evidence; ordinary dispatch and manual
DirectInput remain separate requirements.

## Version and source boundaries

The native September 6 protocols and the three unfinished local movement/key-pan
validators are preserved. The earlier two movement failures remain failures;
the unexecuted 11:40 plan remains preparation. A new complete-stage report must
retain `ARMY_CONTRACT_PASS`, `COMPLETEHD_CONTRACT_PASS` and
`PTILE_CONTRACT_PASS`, with the exact complete manifest and executable. Identical
1024x768 executable bytes do not make an old stage report complete-stage proof.
The separate modal-slots candidate is outside this protocol.

`tools/army_probe_startup.py` owns an explicit startup recipe. Its six animation
startup literals and ordinary slot0 load substitution match the authenticated
historical harness recipe. The compiler checks its geometry sources, exact
transport/token boundaries, breakpoint collisions and CDB line limits. It does
not import a changing runtime harness to obtain startup commands. Historical
harness and validator hashes are retained in their existing sources and reports.

`tools/complete_hd_army_selection_probe.py` preserves the frozen native selection
sequence while checking the new candidate contract. The supplied manifest must
match reconstruction including JSON value types; duplicate/nonfinite JSON is
rejected by the CLI. Packets record the normalized manifest digest, source
receipts, recipe, native observers and disclosed controls. Preparation writes no
files and starts no process.

`tools/complete_hd_army_selection_trace.py` authenticates the original, save,
complete manifest, candidate, packet and actual command bytes. Its initial-map
check consumes the original complete log without stage projection. Native
selection, thread/stack identity, draw pairing, loaded contracts and surface
bounds are checked separately from pixels and cleanup. Sequence-only evaluation
cannot authorize host capture. Even a bound passing trace does not establish
ordinary input, visible composition, endurance or promotion.

`tools/complete_hd_army_movement_probe.py` builds on that selection protocol and
preserves the native movement-v3 observers. It prepares one outward move from
`(16,19)` to `(18,19)`, with preview, confirmation, bounded native input-pump
observations and three stopped capture points. Surface sizes and pointer bounds
follow the selected resolution. Preparation cannot establish movement success;
the full movement trace, pixel audit and owned runtime host are still required.

## Safe checks

From the repository root, with an installed Python interpreter:

```powershell
python -B tools/test_army_probe_startup.py
python -B tools/test_complete_hd_army_selection_probe.py
python -B tools/test_complete_hd_army_selection_trace.py
python -B tools/test_complete_hd_army_movement_probe.py
```

The native-byte preparation fixtures use the user-owned original and inspected
save. Set `CLASH95_ORIGINAL` and `CLASH95_SELECTION_SAVE` if those files are in
nondefault locations. Unavailable local inputs are reported as skipped coverage;
a skip is not runtime evidence. Synthetic trace fixtures exercise parser
acceptance and rejection without manufacturing a runtime report.

## Remaining runtime requirements

A fresh immutable run plan and an owned hidden host are still needed for this
new protocol. Authenticate the exact candidate and commands before starting,
retain every original failure, and capture only at the validated stopped
boundary. Record process identity, deadline, input method, raw artifacts and
verified cleanup. Audit all four frame edges, the footer, all six action cells
and the complete portrait backing in each relevant screenshot.

The movement validator must observe the real path preview and release, a second
native confirmation, both occupancy/XY commits, expected action-point costs,
redraw and true handler return. Empty queues or charged action points do not
prove arrival. Ordinary input must additionally observe the real main-loop call
at `40B233` into `4084A0`; the controlled synthetic return `406FA1` is not that
call site. Keyboard-pan evidence must include key release and a fresh final
camera/redraw observation. See [UNIT_SELECTION_HD.md](UNIT_SELECTION_HD.md) and
[ARMY_TRANSITION_ROUTES.md](ARMY_TRANSITION_ROUTES.md).
